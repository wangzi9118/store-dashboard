# 门店财务运营看板 v5.0

一套面向多门店经营场景的财务数据管理系统。支持 Excel 账目导入、月度手工录入、经营看板、门店 PK、用户权限、导入模板管理和跨设备共享数据。

---

## v5.0 版本主要更新

1. **看板核心指标布局与结构优化**：
   - **营业额实收** 与 **总支出** 并排双 Hero 大卡片展示，均搭载 12 个月迷你柱形图（收入使用天青蓝高亮，支出使用橙红高亮区分）。
   - **本月结余**（营业额实收 − 总支出）提升为卡片主指标，下方展示 **总提现**（子指标）及各自环比数据。
   - **毛利率** 新增子指标 **净利率**，展示在卡片下半区，同样支持同环比联动对比。
   - **深色模式 Tooltip 体验修复**：全局采用主题适配的深色 CSS 气泡提示，彻底解决 Windows 原生 Title 白底白字隐形问题。
2. **经营计算口径修正**：
   - **毛利率** 正式修正为：`(营业额实收 − 订货支出) / 营业额实收`。
   - **净利率** 正式加入核心指标：`本月结余 / 营业额实收`。
   - **本月结余**：`营业额实收 − 总支出`。
3. **Excel 导入模板管理与分发体系**：
   - **模板上传**：管理员可在「权限管理」中上传 `.xlsx` 格式的标准化导入模板，单文件大小最大限制为 5MB。
   - **模板持久化**：模板二进制流持久化于 MySQL `templates` 表，支持多次更新与覆盖，记录上传时间与文件体积。
   - **模板下载**：在「月度录入」页面的【导入 Excel】按钮旁增加【下载模板】功能，具备数据录入/管理权限的用户可一键下载最新模板。

| --- | --- |

## 看板布局

KPI 指标卡片分两行展示：

| 行 | 卡片 | 说明 |
| --- | --- | --- |
| 第一行 | **营业额实收**（Hero · 跨两列 · 蓝紫色迷你柱） | 所有收入渠道金额之和 |
|  | **总支出**（Hero · 跨两列 · 橙红色迷你柱） | 所有支出渠道金额之和 |
| 第二行 | **本月结余**（主指标） + **总提现**（子指标） | 本月结余 = 营业额实收 − 总支出；提现不计入营业额 |
|  | **订货支出**（主指标） + **订货占比**（子指标） | 订货支出 / 营业额实收 |
|  | **工资支出**（主指标） + **工资占比**（子指标） | 工资支出 / 营业额实收 |
|  | **毛利率**（主指标） + **净利率**（子指标） | 毛利率 = (营业额实收 − 订货支出) / 营业额实收；净利率 = 本月结余 / 营业额实收 |

- **全年视图**：下方展示营业额与总支出的月度趋势折线图（含同比），迷你柱 12 个月全亮。
- **月份视图**：迷你柱高亮当前所选月份，所有指标与上一自然月进行环比对比。

## 核心计算规则

```
营业额实收 = 所有收入渠道金额之和
总支出     = 所有支出渠道金额之和
本月结余   = 营业额实收 − 总支出
毛利率     = (营业额实收 − 订货支出) / 营业额实收
净利率     = 本月结余 / 营业额实收
订货占比   = 订货支出 / 营业额实收
工资占比   = 工资支出 / 营业额实收
```

> 营业额实收 ≤ 0 时，订货占比、工资占比、毛利率和净利率均按 0 处理。
>
> 收支明细只用于记录和阅读，**不参与**上述任何计算。

## 快速开始

### 环境要求

- **Node.js 22.5+**（推荐 24）：https://nodejs.org
- **MySQL 8.0+**：本地安装或云托管

### 方式一：运行服务（发布包）

发布包已带构建好的前端（`dist/`）。

1. **安装依赖**：
   ```bash
   npm ci --omit=dev
   ```
2. **配置 MySQL**：复制 `.env.example` 为 `.env`，填入数据库连接参数：
   ```env
   MYSQL_HOST=127.0.0.1
   MYSQL_PORT=3306
   MYSQL_USER=store_dashboard
   MYSQL_PASSWORD=your-password
   MYSQL_DATABASE=store_dashboard
   DEFAULT_ADMIN_PASSWORD=123456
   ```
   服务端启动时会自动从 `.env` 加载环境变量（基于 Node.js `process.loadEnvFile`），无需手动 export。
3. **启动**：
   - Windows：双击 `start.bat`
   - macOS：双击 `start.command`（首次可能需在「系统设置 → 隐私与安全性」允许运行）
   - 或终端执行：`node server.mjs`
4. **打开浏览器**：访问 http://localhost:5174

看到 `Store dashboard server listening on http://0.0.0.0:5174` 即启动成功。

> 升级时只替换代码并重新构建，MySQL 数据库保持不变。

### 方式二：从源码开发

```bash
npm install          # 安装全部依赖（含 devDependencies）
npm run server       # 终端 1：后端 API（默认 5174），需先配置 .env
npm run dev          # 终端 2：前端开发服务（默认 5173，/api 代理到 5174）
```

构建生产文件：`npm run build`（输出到 `dist/`），再用 `npm start` 一并提供页面和 API。

## Excel 导入规则

系统寻找包含"店、月、营业额"表头的工作表作为汇总页，并尝试识别明细工作表。

**汇总页：**
- 门店名称和月份用于定位月度记录
- 渠道中正数归入收入，负数归入支出（支出以绝对值保存）
- `订货总支出`→订货支出，`工资`→工资支出，`提现`/`提取`列→总提现
- 提现不计入收入渠道，避免抬高营业额实收和毛利率
- 全空或全 0 的月份会被忽略
- Excel 中出现不存在的门店时自动创建；观察者导入时需要"门店管理"权限，新门店同样自动加用户名前缀

**明细页：**
- 识别月份、日期、明细/摘要、收入、支出列
- 写入对应月份的收入明细和支出明细，不参与经营指标计算
- 重新导入同一月份时替换 Excel 来源的数据，保留手工新增内容

## 数据存储

生产环境使用 MySQL。启动时会自动创建以下数据表：

| 表 | 用途 |
| --- | --- |
| `app_state` | 业务数据 JSON（门店、月度记录、年度目标） |
| `users` | 用户、密码哈希、角色、上次登录时间 |
| `observer_store_permissions` | 观察者与可查看门店的对应关系 |
| `sessions` | 登录会话令牌哈希和过期时间 |
| `templates` | Excel 导入模板二进制、文件大小、上传时间 |

> 业务数据采用单条 JSON 保存，适合轻量服务器和小团队。不支持高并发协同录入（最后写入结果覆盖之前的）。MySQL 负责持久化，浏览器缓存不会自动覆盖服务器数据。

## 登录和会话

- 登录后设置 `HttpOnly`、`SameSite=Lax` 的会话 Cookie，有效期 7 天
- 令牌以 SHA-256 哈希存储
- 退出登录删除当前会话
- 观察者读取 `/api/data` 时服务端自动过滤未授权门店

## 开发维护约束

修改代码时必须遵守：

1. 营业额实收和总支出必须来自渠道合计，不能改为手工输入
2. 收支明细不参与 KPI、利润率、渠道合计或门店 PK 计算
3. Excel 负数渠道归支出，汇总列必须排除避免重复
4. Excel 全空或全 0 月份必须忽略
5. 重新导入 Excel 时保留手工渠道和手工明细
6. 观察者权限必须在服务端执行，不能只隐藏前端菜单
7. 管理员路由需同时保留前端保护和服务端校验
8. 密码不能明文存储
9. 删除门店时同步删除其月度记录和年度目标
10. 看板全年视图用同比，月份视图用环比，折线图只在全年视图显示
11. 上传导入模板仅限 `.xlsx` 格式，文件大小不得超出 5MB

修改后至少执行：

```bash
npm run build && npm run lint && node --check server.mjs
```
